# Baseline: calendar-driven keep-awake

Written on 2026-11-24 to record the design the app already had before the change notes started.

## Summary

A menu bar app that holds `caffeinate -di`-style power assertions while a calendar event is on, and releases them afterwards.

## Design

- **Calendar source:** EventKit, so it sees whatever the macOS Calendar app shows (iCloud, Google, Exchange through Internet Accounts). You can exclude individual calendars.
- **Keeping awake:** `IOPMAssertionCreateWithName` with `PreventUserIdleSystemSleep` (and `PreventUserIdleDisplaySleep` if "Keep display on" is set). It doesn't spawn `caffeinate`. macOS releases the assertions automatically if the app quits or crashes.
- **When to re-check:** a 30-second timer, plus `EKEventStoreChanged` and `NSWorkspace.didWakeNotification`. `SleepAssertion.enable` does nothing if nothing changed, so the timer doesn't keep recreating assertions.
- **Which events count:** cancelled and declined events never count. All-day events count only if you opt in. You can choose to ignore events marked "Free". If events overlap, it stays awake until the last one ends.
- **Modes:** Auto (follows the calendar), Always awake and Off.
- **Packaging:** SwiftPM executable wrapped into an `.app` by `build.sh`, ad-hoc signed. It needs the Info.plist, or macOS kills it when it asks for calendar access.

## Known limits

- Closing the lid still sleeps a MacBook (the same as `caffeinate`). Superseded by [Closed-lid keep-awake](2026-11-24-closed-lid.md).
- A sleeping Mac runs no code, so the original app couldn't wake the Mac for an event. The [wake from sleep](2026-11-24-wake-from-sleep.md) change addresses this.
